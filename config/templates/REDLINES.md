# REDLINES — 隐私红线与安全偏好

> 与 `CONSTITUTION.md` 同级，**只有宿主能改**。
> 规则数据源：`config/pii-rules.json`（机器可读）；本文件是给人看的执行口径。
> 判定工具：`tools/pii-scan.mjs`（纯本地，零联网）
> 本文件由 `tools/setup.mjs --fix` 从 `config/templates/` 生成，创建日期：{{date}}

---

## 一、三级红线

### L1 硬红线 —— 命中即终止

**范围**：身份证号、银行卡号、护照号、API Key / Token / 私钥 / 密码 / 验证码、指纹人脸虹膜基因等生物特征。

**动作**：立即终止当前操作，不外发、不脱敏后继续、不写进任何可同步目录、不在日志里留原文。
**允许记录**：`{时间, 技能, 规则id}` 三元组。

**唯一例外**：无。宿主临时授权也不放行（确实要处理，先把内容改成占位符再交给工作台）。

### L2 软红线 —— 默认本地，出网需逐条确认

**范围**：真实姓名、手机号、邮箱、详细住址、各类账号、聊天记录、财务数据、医疗信息、情绪记录、家庭关系。

**动作**：
1. 默认只在本地处理（写卡片、写记忆用占位符 `«NAME_1»` 这类格式）
2. 需要出网（发给外部 AI、写进可同步文件）时，**先脱敏再发**，且只发脱敏后的版本
3. 脱敏不彻底时按 L1 处理

> 注意：只有关键词、没有具体值（例如「密码策略」「token 过期」这类讨论）**不算命中**，
> 归 L2 提示，不拦。工具靠 `keywordOnly` 标记来区分——这是 2026-11-07 校准的结论，
> 最早那版把 6 篇正常技术文档里的 5 篇误杀了。

### L3 提示 —— 只记录不拦

**范围**：可能敏感但无法机械判定的内容（如"我老板"这类指代）。
**动作**：记一条提示，不动内容。

---

## 二、判定顺序

先 L1 全量扫 → 再 L2 → 最后 L3。**L1 命中就停**，不做后续判断。

## 三、外发前三问

1. 这段内容里有 L1 吗？有 → 停。
2. 有 L2 吗？有 → 脱敏后只发脱敏版。
3. 收件方是谁？不是宿主自己的机器 → 一律按外发处理。

## 四、姓名词典

`config/pii-rules.json` 的 `nameDictionary` 里填上真名、家人姓名、常用账号前缀。
不填也能跑（靠字段名识别），但命中率会明显下降——**这是初始化时最值得花 1 分钟的一件事**。
