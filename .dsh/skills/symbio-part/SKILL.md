# 零件装配（Part）

**"一切皆零件"的真正含义是：只拿你要的那一小块，而不是装一整个面板。**

## 零件库在哪

```
零件库/
├── 索引.md              # 每个零件：名字 | 一句话 | 来源 | 风险 | 用不用得上
├── 机制/                # 纯方法论（无代码）：如"换会话交接""回执协议"
├── 技能/                # 可直接复制的 SKILL.md 片段
├── 脚本/                # 零依赖小脚本
└── 待评估/              # 想装但没验证的，先扔这
```

初始为空是正常的。**零件库靠一次次的"拆"长出来**，不靠一次买齐。

## 三种来源（按可信度排序）

| 来源 | 做法 | 风险 |
|---|---|---|
| **拆自己的**（最高） | 你已有的某个流程走顺了 → 固化成技能/脚本 | 低 |
| **拆成熟产品的机制**（中） | 看它怎么解决同一个问题，**只抄思路，不搬代码** | 中（需自己验证） |
| **装公开插件**（最低） | 只在确有必要时，且必须读完源码 | 高（权限等同你本人） |

**默认禁止**：来源不明、未签名、需要联网的外部插件。理由：与 L1/L2 红线冲突。

## 步骤

1. **先问清"要解决什么问题"**，而不是"要装什么"。宿主说"我想自动记账"，不要立刻找记账插件，先确认：记什么账、从哪来、给谁看。
2. **查零件库**：`零件库/索引.md` 里有没有现成的；没有就去拆（见下）。
3. **拆**：
   - 找到能做这件事的成熟产品/机制
   - 只提取"解决这一个问题所需的最小机制"
   - 写成 `零件库/机制/<名字>.md` 或 `零件库/技能/<名字>/SKILL.md`
   - 在索引里登记：来源、能力边界、副作用、失效条件
4. **小步试装**：先接到一个场景里跑一次，**不要全工作台铺开**。
5. **体检**：`node tools/memory-lint.mjs` + `/symbio-health`。有不通过就回滚。
6. **登记**：`memory/10-shared/零件台账.md` 追加一行（日期 / 零件名 / 装到哪个场景 / 效果 / 是否保留）。

## 回滚（装之前就要想好）

- 装之前：把将被修改的文件复制到 `memory/90-archive/pre-part-<零件名>-<日期>/`
- 装之后跑不通：把备份复制回去，在零件台账里标记"已回滚 + 原因"
- **没有回滚路径的零件，不许装**

## 硬约束

1. **一次只装一个零件**。三个一起装，坏了不知道是谁的错。
2. **零件必须能被单独关掉**（配置开关或独立目录），不能和主流程焊死。
3. **不许装"全家桶"**：需要 5 个功能只装 1 个，其余记进"待评估"。
4. 涉及联网/读全盘的零件 → 必须过 `/symbio-pii-guard` 评估，并在台账里标红。

## 预期效果

每月 2–3 个零件，三个月后工作台会明显"会干更多活"，而目录不会变乱——这是 D 信号的来源。
