# 派单与回执（Dispatch）

> **这一条是烧钱换来的。** 没有回执判定的多场景协作，会出现"两个 AI 互相客气十小时、账户余额清零、任务没做完"。
> 本技能的唯一使命：**让任务必然闭环，让对话必然终止。**

## 前置

1. `config/symbio.config.json` → `stage.modules.dispatch` 必须为 `true`（默认关闭，B 阶段开启）。
2. 目标场景必须已存在（`memory/20-scenes/<场景>/定位卡.md` 存在）。

## 派单格式（少一个字段，对方可以拒收）

```
[DISPATCH]
from: <本场景名>
to: <目标场景名>
ts: <YYYY-MM-DD HH:mm>
task: <一句话说清要什么，动词开头>
accept: <验收标准：怎样算完成>
need_receipt: yes | no
deadline: <YYYY-MM-DD HH:mm 或 none>
dead_ref: <需要引用的文件路径，可为空>
```

## 派单 vs 公告（先判这一句，错用一次成本极高）

| | 派单 | 公告 / 知悉 |
|---|---|---|
| 对方要做什么 | **动手** | 只是知道 |
| 要不要唤醒 | ✅ **必须**（会花对方一轮） | ❌ 不唤醒（只落盘） |
| 判据（看句子） | 「请你改 / 派单 / 做完回一句 / 改完跑 xxx 复验」 | 「以后就这么办了 / 请注意一下」 |
| 预期回复 | 一条**带证据**的回执 | 无（⛔ 收到知悉一个字都不许回） |

> 真实事故：一天发 36 条"通知"，仅 8 条真进对方会话，其余躺在记忆文件里要等机主点开才看得见 ⇒ **执行率 8/36**。把公告当派单用，就是这种浪费。

## 派单四件套（缺一件对方就得追问）

```
① 现象    ：现在是什么样子（可观察，不要形容词）
② 照哪做  ：哪份文档哪一节 / 哪个工具（唯一出处，别让对方猜）
③ 怎么验  ：做完跑哪个检查、看到什么算通过
④ 回一句  ：明确要回执，写"我在等你的回执"
```

反例：「索引有点乱，你整理一下」　正例：「`索引体检` 报 3 条未登记。照 `二-标准化规范` §6.4 补行。补完跑 `node 索引体检.mjs`，应 ⛔0。**我在等你的回执。**」

## 回执格式（≤200 字，超了就是违规）

```
[RECEIPT]
from / to / ts
status: done | blocked | rejected
result: <一句话结论>
artifact: <产出文件路径>
need_receipt: yes | no      ← 关键字段
```

**闭环规则（唯一一条，但必须遵守）**：

- 收到任务 → 必须回一次 `[RECEIPT]`
- 若自己不是最后一个 → `need_receipt: yes`（对方要继续）
- 若自己是**最后一个完成者** → `need_receipt: no`（**任务到此闭环，任何人不得再回执**）
- 收到 `need_receipt: no` 之后**再发任何消息都算违规**

## 防死循环五条（硬约束）

1. **同一任务同一状态，回执不超过 1 次**。想说第二句 → 合并进第一句。
2. **一次一条，≤200 字**。禁止分多段发。
3. **禁止技术闲聊**。回执里出现"我觉得""顺便问一下""你怎么看"→ 违规，删掉。
4. **同一 `task` 哈希已存在回执** → 不再发起新一轮。
5. **熔断**：出现余额/额度错误、或 CPU/内存 > 90% → 立刻停止派单，把未完成任务写进任务看板并报告宿主。理由只写一句：`已熔断：<原因>`。

## 闭环标记与条数上限（防无限客套烧钱）

- 同一件事消息数 **≤ 3 条**：派单 + 回执 + 收尾知悉（如需要）。
- 末条回执写 **`【结束】`**，明确"这条线到这儿"，对方不得再回。
- 纯确认语（收到/好的/谢谢）⛔ 不许发 —— 不携带信息，只是社交。
- 收到 `need_receipt: no` 之后**再发任何消息都算违规**。

## 台账两查（让"谁欠谁"可查）

派单/回执都要落一行台账（hash / from / to / at / kind / delivered / ack）：
- **我发出、还没人回的** ⇒ 我欠不欠催？
- **别人在等我回的** ⇒ 我是不是让别人空等？
收到回执 ⇒ 自动填 `ack`；超时进"未回执"清单。

## 任务看板写法

`memory/10-shared/任务看板.md` 只保留**未闭环**的条目：

```markdown
| 时间 | 来源 | 目标 | 任务 | 状态 | 回执 |
|---|---|---|---|---|---|
| 11-01 14:30 | knowledge-digest | video-flow | 把卡片导成 2 分钟口播稿 | running | yes |
```

**任务闭环后立刻划掉（删除该行）**，只在 `90-archive/任务台账-<月>.md` 留一行流水。看板必须保持清爽——它是工作台的心跳屏，不是垃圾桶。

## 失败处理

| 情况 | 处理 |
|---|---|
| 目标场景不存在 | 拒绝派单，回 `status: rejected`，说明缺哪个场景 |
| 3 轮内无有效回执 | 判定对方卡住：写进看板 + 通知宿主，**不要自己重发第 4 次** |
| 结果不合格 | `status: blocked` + 明确说缺什么，只发一次；仍不合格则上交宿主裁决 |
| 涉及 L1 内容 | 不允许派单。就地终止并报告"内容命中硬红线，不跨场景传递" |
