# 体检（Health）

**没有体检的自我改造等于自杀。** 每次改动结构、装零件、升级之后，都必须跑这一遍。

## 一、自动部分（先跑脚本）

```
node tools/memory-lint.mjs
```
脚本会检查：文件体积红线、索引缺失、归档目录、空文件、配置合法性。输出 `PASS / WARN / FAIL` 三档。

## 二、八类检查（脚本管不了的部分，逐条人工看）

| # | 类别 | 检查什么 | 不合格的样子 |
|---|---|---|---|
| 1 | 记忆 | 私有记忆是否在长、有没有过期结论没更正 | 三个月没动过 / 全是流水账 |
| 2 | 索引 | 文件多的目录是否都有索引 | 某目录 40 个卡片没有索引 |
| 3 | 技能 | 每个技能是否还在被用；有没有该沉淀成技能的重复动作 | 同一个流程走了 5 次还是手工 |
| 4 | 场景 | 场景是否还在服役；定位卡与实际职责是否一致 | 三个场景干同一件事 |
| 5 | 交接 | 交接是否可读、下个会话能否 30 秒内接上 | 交接里全是过程而不是状态 |
| 6 | 隐私 | 有没有 L2 内容漏在可同步文件里；有没有 L1 残留 | 卡片里出现完整手机号 |
| 7 | 成本 | 本月是否超预算；有没有反复读同一大文件 | 单日超 `cost.dailyBudgetCNY` |
| 8 | 结构 | 目录是否符合六层约定；有没有来历不明的孤儿文件 | `memory/` 根目录散落 md |

## 三、报告格式（写成 `memory/10-shared/体检报告-YYYY-MM-DD.md`）

```markdown
# 体检报告 YYYY-MM-DD

## 结论
FAIL 2 项 / WARN 3 项 / PASS 6 项

## 必须修（FAIL）
1. **场景私有记忆超限**：`20-scenes/knowledge-digest/私有记忆.md` 31KB > 25KB
   → 修法：把 9 月之前的条目移入 `90-archive/knowledge-digest/`，文件头加"已归档至 …"
2. …

## 建议修（WARN）
- …

## 本次通过
- 交接 3.1KB ✅ / 索引齐全 ✅ / 隐私扫描 0 命中 ✅
```

## 四、修复纪律

1. 先修 FAIL，再修 WARN；**一次只修一项**，改完立刻重跑脚本。
2. 修之前先备份：复制到 `memory/90-archive/pre-change-<日期>/`。
3. 涉及删除 → **不真删，一律移动进归档**（`archiveKeepRaw: true`）。
4. 修完在报告末尾追加"已修复"清单和时间。
5. 体检本身的结论也要落盘——**没落盘的体检等于没做**。

## 五、周检节奏（写进工作台习惯）

- 每周日 21:00 自查一次，出报告
- 每月最后一天做一次"结构级"体检：场景是否合并、技能是否沉淀、归档是否要压缩

## 降级

- Node 不可用 → 手工用 `ls -l` / 文件属性看体积，其余照表检查，报告注明"脚本未跑，体积数据为手工估算"
- 发现 L1 残留 → **立即停止体检**，先做隔离（移动到 `30-personal/` 并报告宿主），再继续
