# 记忆写回（Memory Write）

**写错位置比不写更糟。** 所以本技能的第一件事永远是"这段内容该进哪一层"，而不是"赶紧写下来"。

## 六层归位表（先判断，再动笔）

| 内容性质 | 写入位置 | 谁能写 |
|---|---|---|
| 规则、禁区、修改权划分 | `memory/00-constitution/` | **只有宿主**，你不许改 |
| 每轮都要看到的行为准则 | `memory/10-shared/全局须知.md` | 只读（宿主维护） |
| 跨场景的待办/通知/冲突 | `memory/10-shared/任务看板.md` | 所有场景（做完划掉） |
| 关于宿主的稳定认知 | `memory/10-shared/宿主画像.md` | **只有 `symbio-portrait`（C 阶段）** |
| 对宿主的零散观察 | `memory/10-shared/画像参考.md` | 所有场景（只追加） |
| 本场景的项目进展与决策 | `memory/20-scenes/<场景>/私有记忆.md` | **只有本场景** |
| 换会话要交接的进度 | `memory/20-scenes/<场景>/当前交接.md` | 只有本场景（覆盖写） |
| 私人档案（不参与主线） | `memory/30-personal/` | 只有宿主 |
| 过期/超量的历史 | `memory/90-archive/` | 只能追加，不许删 |

## 前置检查

1. 读 `config/symbio.config.json` → `stage.modules.memory-write` 为 `true`。
2. **隐私卡口（第二道）**：内容先过 `/symbio-pii-guard`。L1 终止；L2 一律写占位符，真值只允许进 `30-personal/`（且需宿主明确同意）。
3. **读优先**：写入前先读目标文件当前内容，避免重复、避免覆盖别人的段落。

## 写入规则（五条）

1. **带来源与时间**：每次追加都以 `- [YYYY-MM-DD] ` 开头，必要时附来源（卡片文件名/会话）。
2. **只追加，不重写**：除 `当前交接.md`（覆盖写）外，一律在末尾追加，**不得删除他人内容**。
3. **去重**：已有等价条目就不再写；要修正旧结论，写成"`[更正 YYYY-MM-DD] 原结论 X → 现结论 Y，原因…`"，保留历史。
4. **体量红线**：写前检查大小。
   - `私有记忆.md` > 25KB → 把最旧的 1/3 移入 `90-archive/`，在文件头写一行"已归档至 <路径>"。
   - `当前交接.md` > 4KB → 只保留"当前状态 / 下一步 / 未决问题 / 关键路径"四段，其余归档。
5. **写完自检**：`node tools/memory-lint.mjs`，有 FAIL 就修到过。

## 四条内容标准（不合格就别写）

- **可验证**：写"宿主偏好先看结论再看依据"，不写"宿主喜欢高效"。
- **有触发条件**：写"当涉及 X 时，做 Y"。
- **可执行**：写"路径用绝对路径"，不写"注意路径问题"。
- **不写废话**：不写"今天聊了很多""收获很大"。

## 交接段写法（覆盖写，4KB 内）

```markdown
## 当前状态
<一句话：做到了哪一步>

## 下一步
1. <具体动作，带文件路径>

## 未决问题
- <问题 + 卡在哪>

## 关键路径
- 卡片：memory/20-scenes/knowledge-digest/cards/…
- 索引：memory/20-scenes/knowledge-digest/cards/索引.md
```

## 失败处理

- 目标文件不存在 → 先按模板创建，再写；不要凭空覆盖成新文件。
- 权限不足/被占用 → 报告具体路径与错误，**不要静默丢弃内容**；把待写内容贴在对话里让宿主手动落盘。
- 不确定该写哪一层 → 写进 `任务看板.md` 并标注"待定层"，让宿主决定。
