# 吞噬进化（Evolve）

> **默认状态：未启用（C 层）。** 技能在位、可手动调用，但不自动跑——它会解剖外部产品并改自己。
> 依赖 `symbio-part` / `symbio-health` / `symbio-pii-guard`；面板上的虚线圈是有意为之，不是缺件。

> 原则：**拿来主义，但必须亲眼过目；可以学机制，不可以搬代码。**
> 铁律：**改造的前提是你能验证它没坏。**

## 三步法

### 第一步：解剖（只读，不改）

对目标对象（一个软件、一套机制、一个产品）产出一份报告，固定四段：

```markdown
# <对象> 解剖报告（YYYY-MM-DD）

## 1. 它解决了什么问题
<一句话>

## 2. 它怎么做的（机制层）
- 记忆：……
- 上下文：……
- 协作：……
- 成本：……

## 3. 它的代价
<哪一步最脆、最贵、最难维护>

## 4. 可为我所用的部分
| 机制 | 我的现状 | 差距 | 是否值得抄 | 落地成本 |
|---|---|---|---|---|
| …… | …… | …… | 是/否 | 低/中/高 |
```

**禁止**：把闭源软件的功能清单当"可抄清单"；只写"它很强"这种结论。

### 第二步：选一件（不要一次抄三件）

从第 4 段里挑**一行**，写成可执行提案：

```markdown
## 提案：把 <机制> 装进 <场景>
- 改哪个文件：
- 预期效果：
- 如何验证生效（可量化）：
- 坏了怎么回滚（备份路径）：
- 是否需要新增依赖：是/否
```

**先给宿主看提案，等明确同意再动手。** 宿主没点头就只能停在提案。

### 第三步：小步实施 + 验证 + 留痕

1. 备份：`memory/90-archive/pre-evolve-<日期>/`
2. 只改提案里列的文件，**不改别的**
3. 跑验证：提案里写的验证方法 + `node tools/memory-lint.mjs`
4. 通过 → 写进 `memory/10-shared/共享记忆.md`（"我们学到并采用了 X"）
5. 不通过 → 立刻回滚，把失败原因写进报告（**失败的记录比成功的更值钱**）

## 红线（违反即停止）

1. **不搬闭源源码**。学思路可以，复制代码侵权。
2. **不改 `00-constitution/`**。进化不能改宪法，这是唯一不可进化的部分。
3. **不引入联网依赖** 来做"能力升级"（与隐私红线冲突）。
4. **每改必体检**。没体检的改动一律视为未完成。
5. **一次只进化一个点**。同时改三处，出问题无法定位，也回滚不了。

## 与其他技能的衔接

- 需要新增一项长期能力 → 走 `/symbio-part` 固化成零件
- 改完 → 立刻 `/symbio-health`
- 学到的关于宿主的偏好 → `/symbio-portrait`

## 预期效果

每次进化都应该留下两样东西：一个**可验证的改进**，和一份**可复用的报告**。三个月后回看报告目录，就是工作台的成长史。
