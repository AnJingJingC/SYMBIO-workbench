# 隐私守门（PII Guard）

**这是整个工作台的第一道闸门，先于一切动作执行。** 原则：默认本地、默认保守、默认不发。

## 适用时机（三道卡口）

| 卡口 | 时机 | 谁调用 |
|---|---|---|
| ① 摄入前 | 原始资料进入工作台之前 | `symbio-intake` |
| ② 写记忆前 | 任何内容写入 `memory/` 之前 | `symbio-memory-write` |
| ③ 出网前 | 任何内容将要离开本机（调用外部 API、上传、分享、粘贴到网页）之前 | 所有技能 |

## 判定流程

1. **读规则**：`config/pii-rules.json`（L1/L2/L3 三级 + 占位符映射 + 姓名词典）。
2. **先跑脚本**（本地、零依赖、不出网）：
   ```
   node tools/pii-scan.mjs --text "<待检文本>"
   node tools/pii-scan.mjs --file <路径>
   ```
   输出 JSON：`{level, hits:[{level,id,kind,matches,positions}], verdict}`
3. **脚本没覆盖到的，用语义补判**（只读文本，不发出去）：
   - 含具体人名、亲属关系、住址、单位、病情、财务数字、私聊原文 → 按 L2 处理
   - 只是"某人""他们""一个朋友"这类泛化表述 → 不拦截
   - 拿不准 → **一律按高一级处理**（宁可误拦，不可漏放）

## 三种结论与动作

### L1 → BLOCK（硬红线）
命中身份证、银行卡、护照、API Key、私钥、密码/验证码/生物特征。
- **立即终止**当前任务，不继续、不重试、不"脱敏后继续"。
- 回复只允许一句：`已阻断：内容命中 L1 硬红线，未做任何处理、未发送任何内容。`
- **不许复述命中内容**，不许在日志里记录原文，只记 `{时间, 技能, 命中规则 id}`。

### L2 → REDACT（软红线）
命中真名、手机号、邮箱、住址、账号、聊天记录、财务/医疗/情绪。
- 默认动作：**本地处理**，原文不出网。
- 若确实需要出网：替换为占位符 `«NAME_1» «PHONE_1» «ADDR_1»`，把"替换清单"列给宿主，**逐条确认后才可发出**；宿主没明确说"可以发"，就是不可以。
- 替换必须**双向可还原**：在本地留一份映射表 `memory/90-archive/redact-map-<日期>.json`，不随内容外发。

### L3 → RECORD（观察项）
昵称、单位、项目代号、城市。
- 不拦截、不脱敏；把观察项追加到 `memory/10-shared/画像参考.md`（一行一条，带日期）。

## 输出格式（给调用方看，固定三行）

```
判定：BLOCK / REDACT / PASS
命中：L1-<规则id> ×<次数>；L2-<规则id> ×<次数>
动作：已终止 / 已脱敏（清单见下）/ 可直接使用
```

## 红线（本技能自己也不能破）

- **绝不把待检文本发给任何外部服务做"智能识别"**，包括模型 API。判定只能靠本地正则 + 本地语义判断。
- 不建"敏感词日志库"。命中记录只存规则 id 和时间，不存原文。
- 宿主问"这段到底是什么内容被拦了" → 只回答类型（例如"含身份证号"），不回答具体值。

## 降级

- 脚本跑不起来（没装 Node）→ 手工按 `config/pii-rules.json` 的 keywords 逐条比对，并在结论里注明"手工判定，置信度较低"。
- 规则文件损坏 → **默认全部按 L2 处理**（保守兜底），并提示宿主修复 `config/pii-rules.json`。
