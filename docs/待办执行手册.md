# 待办执行手册（v0.3.7 之后）

> 全部动作需要你本机执行（沙箱不能代 push、不能代装、不能注册计划任务、不能真机登录）。
> 按顺序做，每步都有「预期结果」和「失败怎么办」。全程约 20 分钟。

---

## 步骤 1 · 装 v0.3.7（5 分钟，可选但建议）

**为什么**：0.3.7 起面板工具箱计数逻辑已适配新内部工具；不装也能用，但版本会对不上。

1. 打开 DSH Desktop，把 `E:/SYMBIO/workbench/INSTALL-PROMPT.txt` 整个文件内容粘进会话。
2. 它会调用 `install_local_workbench({ path: "...symbio-workbench-0.3.7.tgz", replace: true })`。

**预期**：返回 `applied`，宿主显示 `symbio-workbench+0.3.7+...`；面板正常加载。

**失败**：若报 `restart-required`，重启宿主后再看面板。

---

## 步骤 2 · 推送发布仓到 GitHub（3 分钟）

```sh
cd /e/symbio-publish
git push -u origin main
```

**前置**：GitHub 上已有空仓库 `AnJingJingC/SYMBIO-workbench`（public，不要勾 README/LICENSE，否则要先 pull）。

**预期**：`main -> main`，`branch 'main' set up to track 'origin/main'`。

**失败排查**：
| 报错 | 原因 | 处理 |
|---|---|---|
| `Repository not found` | 仓库没建 / 名字不对 / 无权限 | 去 GitHub 建 `SYMBIO-workbench`，确认账号是 AnJingJingC |
| `Authentication failed` | 凭据失效 | 弹出登录窗就登录；或用 Personal Access Token 当密码 |
| `rejected (fetch first)` | 远端非空 | `git pull --rebase origin main` 后再 push |
| `src refspec main does not match` | 分支名不是 main | `git branch -M main` 后重试 |

**推送后自查**（浏览器打开仓库应看到）：`package.json`、`dsh/`、`src/`、`lib/`、`tools/`、`shell/sites/`、`.dsh/skills/`、`docs/`、`icon.svg`；**不应有** `memory/`。

## 步骤 3 · 上传工作台市场（5 分钟）

1. 打开 mydsh.xyz 的发布/提交入口，登录。
2. 上传 `E:/SYMBIO/workbench/symbio-workbench-0.3.7.tgz`（**注意版本号是 0.3.7**，别拿旧的）。
3. 核对市场卡片字段：`name=symbio-workbench`、`version=0.3.7`、`author`、`icon.svg`、`repository=https://github.com/AnJingJingC/SYMBIO-workbench`。
4. 提交后**从市场页面反向装一次**，验证"从市场安装"这条链路真实可用。

**失败**：若市场校验报 repository 不可达，先确认步骤 2 的 push 成功且仓库 public。

## 步骤 4 · 注册每周体检计划任务（2 分钟）

用 **PowerShell** 或 CMD（无需管理员），执行：

```bat
schtasks /Create /F /TN "SYMBIO 记忆体检" /SC WEEKLY /D SUN /ST 09:00 /TR "cmd /c E:\SYMBIO\tools\lint-weekly.cmd"
```

**预期**：`成功: 已创建计划任务 "SYMBIO 记忆体检"。`

**立刻验证一次**（不用等到周日）：

```bat
schtasks /Run /TN "SYMBIO 记忆体检"
```

几秒后看 `E:\SYMBIO\reports\` 是否出现 `体检-<今天>.json`。

**管理命令**：
```bat
schtasks /Query /TN "SYMBIO 记忆体检"     :: 查状态/下次运行时间
schtasks /Delete /TN "SYMBIO 记忆体检" /F :: 不想要了就删
```

**失败**：报"拒绝访问"→ 用管理员 PowerShell 再跑；报路径错误 → 确认 `E:\SYMBIO\tools\lint-weekly.cmd` 存在。

## 步骤 5 · 桥多站校准（可选，10 分钟；不校准就别用这三个站）

**终端 A（常驻）**：
```sh
cd E:/SYMBIO/shell
npm run bridge
```
看到监听 `127.0.0.1:31239` 即成功。

**终端 B（校准）**：

```sh
cd E:/SYMBIO/shell
node probe-site.mjs deepseek
```

三种结果对应三种动作：

| 结果 | 含义 | 动作 |
|---|---|---|
| `calibrated: true` | 三选择器全命中且已登录 | 把 `sites/deepseek.mjs` 的 `verified` 改 `true`、`verifiedFields` 三个全 `true` |
| `loggedIn: false` | 没登录 | 先开窗手动登录（见下），再重探 |
| `matched.answer: false` | 没问过就没有回答区 | 在窗口里手动问一句，等回答出现，再重探 |

**开窗手动登录**（壳绝不代填，必须你自己登）：
```sh
curl -X POST "http://127.0.0.1:31239/webai/show?site=deepseek"
# 在弹出窗口里手动登录
curl -X POST "http://127.0.0.1:31239/webai/hide?site=deepseek"
```
`qianwen`、`zhipu` 同理，把 `deepseek` 换掉即可。

**重要**：选择器是猜的。探测若 `matched.input:false`，说明猜测错了——把 `probe-site` 输出里的候选元素（`dom` 字段）发我，我按实测改。

## 步骤 6 · 无人循环验收（5 分钟）

前置：终端 A 的桥在跑，且 `doubao` 已登录（豆包已校准，先用它）。

1. 造一篇投递文件（≤2800 字，超过会进 `_too-long`）：
   ```sh
   mkdir -p "E:/SYMBIO/memory/50-inbox"
   ```
   在 `E:/SYMBIO/memory/50-inbox/` 下新建 `测试投递.md`，随便写几百字。
2. 跑一次：
   ```sh
   cd E:/SYMBIO
   node tools/autopilot.mjs --once
   ```
3. **预期日志**：`处理 测试投递.md` → `已落卡 cards/2026-11-04-测试投递.md；原文归档 memory/50-inbox/_done/测试投递.md`
4. **验收**：`memory/20-scenes/knowledge-digest/cards/` 出现新卡，`索引.md` 多一行；面板「知识卡片」计数 +1。
5. 想常驻：`node tools/autopilot.mjs`（窗口别关；每 30s 扫描 + 文件落地即触发）。

**失败对照**：
| 日志 | 原因 | 处理 |
|---|---|---|
| `桥不可达` / `fetch failed` | 桥没起 | 回步骤 5 终端 A |
| `not-logged-in` | 该站掉登录 | `/webai/show?site=doubao` 手动登录 |
| `失败 3 次进 _failed` | 连续出错 | 看 `_failed/` 里的原文，修好环境后手动移回 inbox |
| 进了 `_too-long` | 正文 >2800 字 | 自己切成多篇，或先人工消化 |
