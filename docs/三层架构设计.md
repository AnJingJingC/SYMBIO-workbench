# SYMBIO 三层系统架构设计（反推方案）

> 依据：作者公开仓库 `luanyujia-workbench` 的真实实现 + 我方「标准 DSH 0.2.1」约束。
> 性质：**反推设计**，不是作者代码照搬。作者桥绑 Electron `<webview>`，未用 Playwright；本方案把其能力抽象为可移植的通用结构。
> 配套图：Ardot《SYMBIO 三层系统架构方案》。

---

## 0. 设计前提（三条硬事实）

1. 作者的免费桥 = **Electron `<webview>` + 本地 HTTP 桥（127.0.0.1:31239）**，不是 Playwright。
2. 作者的"薄壳" = **骨架 + 每站适配器**，真实各站实现未公开；它依赖壳的 webview IPC。
3. 我方运行在**标准 DSH 0.2.1 + `.dsh/skills`**，没有自研壳 → 壳层必须是**新增**，且与 DSH 解耦。

---

## 1. 总览：四层与单一依赖方向

```
┌─────────────────────────────────────────────┐
│ ① 多场景 UI 层        （渲染 + 交互，无权限） │
├─────────────────────────────────────────────┤
│ ② 绑壳免费桥层        （能力适配 + 通信）     │
├─────────────────────────────────────────────┤
│ ③ 自研 Electron 壳层  （进程 + 权限 + 权威）  │
├─────────────────────────────────────────────┤
│ ④ 底层能力            （DSH / FS / 网页 / HTTP）│
└─────────────────────────────────────────────┘
```

**依赖铁律：只允许 ↓ 单向下行调用。** 上层调用下层；下层永不反向 import / require 上层。跨层通信只能通过**显式契约**（`app.*` / bridge HTTP / IPC 通道），不允许共享全局对象。

## 2. ① 多场景 UI 层

### 2.1 结构与职责

| 组件 | 职责 | 不属于它 |
|---|---|---|
| 标签栏 Tabs | 场景切换、拖拽换位、未激活收成图标 | 不持久化顺序（只上报主进程） |
| 面板网格 Grid | 按 `col/row/w/h` 摆放面板 | 不算布局、不直接读盘 |
| 面板注册表 Registry | `file/view/harness/mcp/reserved` 五类渲染器 | 不创建窗口、不持有权限 |
| 场景配置 Scene JSON | `scenarios/<id>.json` = {id,name,panels[]} | 不含运行时状态 |
| 状态栏 | 引擎状态 / 当前场景 / 当前会话 / 面板数 | 不做业务判断 |

### 2.2 数据结构（唯一真相源）

```json
{
  "id": "knowledge-digest",
  "name": "知识消化",
  "description": "把资料消化成知识卡片",
  "panels": [
    { "id": "kd-files", "type": "file",    "col": 0, "row": 0, "w": 4, "h": 6 },
    { "id": "kd-view",  "type": "view",    "col": 4, "row": 0, "w": 8, "h": 6, "filesPanel": "kd-files" },
    { "id": "kd-ai",    "type": "harness", "col": 0, "row": 6, "w": 12, "h": 4,
      "sessionTitle": "...", "sessionId": "...", "pinTarget": "..." }
  ]
}
```

### 2.3 组件复用策略

- **面板 = 数据 + 渲染器**：加一种面板 = 往 `RENDERERS` 注册一个函数，**不改壳**。
- **场景 = 面板组合**：加一个场景 = 加一份 JSON，**不改代码**。
- **同类型跨场景复用**：`file` 面板可同时被多个场景实例化；用 `id` 前缀（`kd-`、`bz-`）防存储键串台。
- **未知类型降级**：`type` 未注册 → 渲染一行灰字提示，**不报错、不白屏**。

### 2.4 边界与约束

- UI **不直接读盘**：一律经 `app.file.list/read`（预加载暴露）。
- **tab 顺序只报主进程**，UI 不本地持久化（单一权威）。
- 面板位置是**数据**，不是代码常量。
- 面板 id 必须带场景前缀，否则抢同一存储键。

## 3. ② 绑壳免费桥层

### 3.1 通信机制（三层转发）

```
调用方(付费Agent/MCP/面板)
   │  POST http://127.0.0.1:31239/webai/ask   {site, question}
   ▼
桥服务（主进程）
   │  找/唤起 site 对应的 <webview>（partition=persist:webai-<key>）
   ▼
站点薄壳 site（每站一个配置对象）
   │  loggedIn → fill → send → waitFirstToken → waitStable
   ▼
webview guest（已登录 Chromium）
   │  取回文本
   ▲
   结果原路返回（JSON {ok, text} | {ok:false, errorType}）
```

### 3.2 契约定义

**HTTP / MCP 入参**
```ts
ask({ site: string, question: string }) => Promise<
  | { ok: true;  text: string }
  | { ok: false; errorType: "not-logged-in" | "guest-dead" | "selector-stale" | "empty-answer" | "timeout"; message: string }
>
```

**站点薄壳对象（唯一配置面）**
```js
{
  id, name, url,
  loggedIn(page): Promise<boolean>,
  inputSel: string,
  send(page): Promise<void>,
  answerSel: string,
  wait: { firstTokenMs:20000, stableMs:1200, hardTimeoutMs:180000 },
  profileDir: string|null
}
```

**壳对内暴露（供桥用）**
```ts
bridge.openPage(siteId, url, {profileDir}): Promise<Page>
bridge.fill(page, selector, text): Promise<void>
bridge.waitFor(page, selector, timeoutMs): Promise<void>
bridge.waitStable(page, selector, {stableMs, timeoutMs}): Promise<string>
```

### 3.3 依赖

- **依赖壳层**：webview 生命周期、`partition=persist` 持久登录态、主进程桥 HTTP 服务、Electron 真输入事件（`insertText`/`sendInputEvent`）。
- **不依赖**：Playwright / CDP / 任何外部浏览器驱动。

### 3.4 错误模型（必须分流，不许混）

| errorType | 判定 | 处置 |
|---|---|---|
| not-logged-in | `loggedIn()` 为 false | 提示手动登录一次，**不自动登录** |
| guest-dead | webview guest 失效 | 重建 → 摘挂 → 重赋 src，三路自救 |
| selector-stale | 取到空/结构不符 | 报"选择器可能过期"，不改配置 |
| empty-answer | 等待超时仍空 | 如实报错，不编造 |
| timeout | 超 `hardTimeoutMs` | 中止并返回 |

### 3.5 约束

- 只监听 `127.0.0.1`，**不对外**。
- **同站不并发**（否则串话），桥服务串行排队。
- **先等首帧出现，再等文本 stable**，两步不可合并。
- **机密闸在调用前**：含 密码/token/证件/银行卡/手机号 → 直接拒发。
- 只适合**一问一答纯文字**；长任务会掉登录/弹验证。
- 不自动登录（触发风控、难排查）。

## 4. ③ 自研 Electron 壳层

### 4.1 进程架构

| 进程 | 角色 | 核心职责 | 边界 |
|---|---|---|---|
| **Main Process** | 能力 + 权威 | 窗口/标签管理、桥 HTTP 服务、IPC 路由、会话 RPC 代理、文件系统（只读前 8KB）、单实例锁、崩溃守护 | 不渲染 UI |
| **Preload** | 安全桥 | `contextBridge` 暴露 `app.*`；`contextIsolation=true`；`nodeIntegration=false` | 不暴露原始 `require`/`fs` |
| **Renderer** | 界面 | 建标签+网格、面板渲染、webai-bridge.js、mcp-panel.js | 无 Node 权限、不直接读盘 |
| **webview Guests** | 网页隔离 | 每站一个 Chromium，`partition=persist:webai-<key>`，持有登录态 | 只被桥驱动 |

### 4.2 对 UI 暴露的 `app.*` 契约

```ts
app.file.list(dir): Promise<FileNode[]>
app.file.read(path): Promise<string>        // 只读前 8KB
app.session.current(): Promise<{id,title}>
app.session.rotate(): Promise<{id,title}>
app.tabs.setOrder(ids: string[]): Promise<void>   // 单一权威
app.window.minimize/close(): void
```

### 4.3 边界

- **UI 只能通过 `app.*` 触达能力**，不得跨进程直连。
- **桥只能通过 bridge 服务/webview 触达网页**，不得让 renderer 自建 webview。
- **会话身份靠"表 + 卡认领"**：引擎不按场景注入任何东西。

### 4.4 约束

- 能力最小暴露（`contextIsolation` + 白名单）。
- **单实例锁**，防多开抢桥端口。
- 打字走**真输入事件**（`insertText`/`sendInputEvent`），直接赋值对 contenteditable 无效。
- guest 失效**不自作登录**，按三路自救。
- 桥进程只绑本机。

## 5. 模块边界矩阵（谁拥有什么）

| 能力 | 拥有者 | UI 可否直接用 | 桥可否直接用 | 越界后果 |
|---|---|---|---|---|
| 文件读写 | Main | ❌ 经 `app.file` | ❌ | 权限泄漏 |
| 网页驱动 | Bridge + Guests | ❌ | ✅ | 串台/风控 |
| 会话切换 | Main（RPC） | ❌ 经 `app.session` | ❌ | 指向已归档会话 |
| tab 顺序 | Main | ❌（只上报） | ❌ | 多开顺序冲突 |
| 场景布局 | UI（JSON） | ✅ | ❌ | 布局写死 |
| 站点选择器 | Bridge（site 对象） | ❌ | ✅ | 桥失效 |

## 6. 依赖关系（文字图）

```
UI ──app.*──▶ Preload ──IPC──▶ Main ──▶ FS / DSH 引擎 / 会话 RPC
UI ──bridge HTTP/MCP──▶ Bridge 服务(Main) ──▶ webview guest ──▶ 网页
Bridge ──bridge.openPage/fill/waitStable──▶ Main(webview 管理)
UI ──(不直接)──▶ 任何底层
```

- **上行零依赖**：Main 不 import UI，Bridge 不 import UI 渲染器。
- **横向弱依赖**：UI 与 Bridge 仅通过 HTTP/MCP 契约通信，可独立替换。

---

## 7. 全局关键约束（跨层）

1. **单向下行依赖**，跨层只走显式契约。
2. **权限最小化**：renderer 无 Node；桥只绑本机。
3. **单一权威**：tab 顺序、会话状态只在 Main。
4. **数据驱动 UI**：布局与场景是 JSON，不是代码。
5. **失败可解释**：未注册类型灰字、桥错误分流、guest 三路自救。
6. **机密前置拦截**：桥调用前过机密闸。
7. **不自动登录、不并发同站、不把长任务丢给免费桥**。

### 第 3 步真机校验的实际发现（2026-11-04）

真机跑不等于"能跑"两个字，这一轮抓出并修掉了 5 个只在真实环境才暴露的问题：

1. **`ELECTRON_RUN_AS_NODE=1`** 让 electron 退化成纯 Node → 新增 `shell/launch.mjs` 自动清除。
2. **自检与正式壳各用一套 IPC**（自检报 3 个 `No handler registered`）→ IPC 白名单抽到 `core/ipc.mjs` 唯一真源。
3. **SPA 水合前探测**导致选择器全 false → 以"目标元素真命中"为水合信号 + 自适应重探。
4. **答案选择器命中用户气泡**（返回的就是自己的问句）→ 改指 `receive_message > message_content`，并改为"只认发送后新增的最后一条"。
5. **正文混入推荐卡片/搜索状态行** → 站点层 `clean()` 保守去噪。

其中第 4、5 条已固化为 `shell/test-site.mjs` 的 14 条回归断言。

**仍然未验证的**：登录态下的稳定问答（匿名额度耗尽后会弹登录框，需宿主手动登录一次；壳不代填账号）。
