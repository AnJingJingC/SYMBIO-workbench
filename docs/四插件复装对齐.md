## 四、复装路径与纪律（架构唯一合法方式）

1. 只能由**宿主会话内的 Agent** 调 `plugin_manager.install_bundle({spec})`；禁止外部 CLI、改 profile 文件、手动 pnpm 绕过——宿主官方契约明确这些步骤由 `install_bundle` 自己完成。首次安装的可复制提示词见 `docs/四插件安装提示词.md`。
2. 标准包用包名 spec；两个非标准包**优先用 E 盘备份 `E:/SYMBIO/_backup/offline-plugins/` 的 tgz**，E 盘不可用再回退 D 盘源码目录重打包（本文第三节）。
3. 每次安装后逐条回报 `application` 原文，**只有 `applied` 才算装上**；peer 告警先照实回报、不自加版本豁免、不自行重启。
4. 复装后核对 desired.json 是否回到第一节四个 hash，缺项或不符即视为未对齐。

## 五、触发条件与边界

- **何时复装**：宿主更新 dsh 内核、重装/重置 profile、或某插件失败需回退时，先比对 desired.json 四个 hash 是否在案；缺项或不符再复装，不要日常重装。
- **意图**：本文只记录已核实事实与路径，便于对齐；不预测未来内核版本是否再次触发 peer 校验。
- **无关项**：这四个是宿主插件，与 symbio-workbench v0.5.5 工作台包是两回事，不改变工作台包 md5 与发布仓状态。

四插件之外，宿主还试图装一个实验性 agent-team，但每轮启动都被 peer 校验打回，`.generations-deferred.json` 记录 `failedAt 2026-11-19T15:20:41Z`、`retryAfter 21:20` 已过仍未恢复。核实结论如下，**不是工作台能修的**：

- **它要什么**：`@deepseek-ai/dsh-experimental-agent-team-profile@0.1.5-alpha.2` 声明依赖 `@deepseek-ai/dsh-experimental-agent-team@^0.1.5-alpha.2`、`@deepseek-ai/dsh-experimental-tool-agent-team@^0.1.5-alpha.2`，peer `@deepseek-ai/cordis@^4.0.2`。
- **本机有什么**：全局 npm 的 dsh 内核里确实带这两个包，但版本是 **0.2.0-rc.2**——落在 `^0.1.5-alpha.2`（等价 `>=0.1.5-alpha.2 <0.2.0`）之外，semver 直接不匹配。cordis 是 4.0.5，满足 `^4.0.2`，但 profile 的 pnpm 闭包里没有它（在全局内核里，未被解析进 profile）。
- **为什么外部修不了**：这是宿主上游的**版本错配**（profile 期望 0.1.x 依赖，主机只带 0.2.0-rc.2），不是缺文件。插件安装只能走宿主 `plugin_manager.install_bundle`，外部 CLI/pnpm 补包既违规、也解决不了 semver 不匹配。
- **要修只能宿主侧做**：宿主发一个与 0.2.0 内核对齐的 agent-team-profile 新版本，或显式对这两个依赖放宽版本约束后重装。工作台侧无动作、也不该假装能装。
