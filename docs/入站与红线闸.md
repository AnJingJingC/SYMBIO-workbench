# 入站与红线闸：补「入口」和「出口」各一道

> 起因：对照作者第 20 期《AI 全自动交付，未来已来》（2026-11-18）。他把客户消息当触发器、把价格退款做成代码过滤；我们原来两头都缺——只能在对话里等人开口，也没有任何一道闸管"说出去的话"。
> 本文只写已经落地、可跑、有自测的那部分；没做的写在最后一节，不写成已完成。

---

## 一、红线闸（出口）

**它管什么**：对外文本里的**承诺与合规**——价格、退款、收益、绝对化、合规词、贬损、时效承诺。三道既有闸（隐私、花费、负载）都在管"进来的东西"，这道是第一道管"出去的话"。

**用法**

- `node tools/redline-scan.mjs --text "这段话"`
- `node tools/redline-scan.mjs --file msg.txt`
- `echo "..." | node tools/redline-scan.mjs --stdin`
- 加 `--explain` 看命中原因与上下文；加 `--json` 给程序用
- `node tools/redline-scan.mjs --check-rules` 自检规则能否编译

**退出码决定要不要发**

- `0` 放行（无命中，或只有 L2）
- `1` 只有 L2 提醒：不拦，但建议再看一眼（限时、名额、时效承诺、贬损同行）
- `2` L1 硬拦：别直接发，要么删掉承诺，要么人来确认
- `3` 规则或用法有问题：**按"先别发"处理**，不要当成 0

**规则怎么改**

- 主规则 `config/redline-rules.json`，进版本库；每条有 `id` / `level`（L1 硬拦、L2 提醒）/ `why` / `patterns`（JS 正则源码）。
- 本机白名单 `config/redline-rules.local.json`，**只允许 `allowlist`**；写别的字段会被拒（3），防止一份本地文件把整道闸关掉。
- 白名单是**遮蔽**不是跳过：命中的短语被替换成等长占位符再匹配，所以"解释零风险是什么"这类句子可以放过，而同一句里别处的"零风险"承诺仍会被拦。

**纪律**：判不出就不放行。规则文件读不到、JSON 坏、正则编译不过、规则集为空，一律退出 3——空规则集等于放行一切，所以直接拒绝启动。

## 二、入站（入口）

**它管什么**：把"外部来的消息"变成看板上的任务，而不是只在你开口后才动。

**用法**

- 把来件丢进 `memory/50-inbox/_inbound/`（`.md` 或 `.txt`，一件一个文件，正文是原话）
- `node tools/inbound.mjs --once` 处理一轮就退出；`--interval 60000` 常驻每 60 秒扫一次
- `--once --dry` 只判定不派单、不动文件；`--json` 给程序用

**链路**：文件 → 隐私闸 → `route.mjs` 判场景（关键词优先、判不准才问免费桥）→ `bus dispatch` 落看板 → 归档到 `_routed/`。

**三个去向，各有含义**

- `_routed/` 派单成功；`_inbound-log.md` 记了场景与任务 hash
- `_unrouted/` 判不出来，**不硬猜**，等人指派
- `_blocked/` 隐私命中，**连路由都不走**——因为路由可能把原文发给免费桥，那就等于外发

**两条容易踩的纪律**

- 隐私闸必须先于路由：顺序反了，桥就成了外发通道。
- 重复件按正文 hash 识别，跳过且不重复派单；同一条消息转发两次不会变成两个任务。

**和顶层 `50-inbox/*.md` 的区别**：顶层是知识材料（`autopilot` 消化成卡片），本目录只做任务派单。混放会让同一份东西被两条链路各处理一遍。

## 三、自测与边界

**自测**：`node tools/dev/selftest.mjs` —— 新增 29 条断言（红线 16 + 入站 13），全量 190/0。红线闸的重点断言是四个 fail-closed 分支（坏 JSON、坏正则、空规则、本地改规则），入站的重点是"判不出来不硬猜""隐私命中不进看板""重复件不重复派单"。

**没做的部分（如实标注）**

- **没接面板按钮**。`listTools()` 仍是 6 个业务工具，红线闸与入站是 CLI 先行。要上按钮得把工作台包升到 0.5.6，而新版需要宿主重新装一次（`install_local_workbench`），不是我在这一侧能代做的。
- **不接微信/企业微信**。个人微信无官方接口，接它只能走界面自动化，随客户端版本失效且有平台规则风险；本链路只做到"你转发一次，其余自动"。要更自动，正路是邮件 IMAP 轮询（协议标准、可长期跑），需要账号与授权码。
- **入站不负责回复**。它只把件变成任务；对外的回复文本仍要过红线闸，这两件目前是两个命令，可以由你串起来，也可以等面板把两步合成一个按钮。

## 四、什么时候用

- 有人给你发消息/邮件谈业务，你要让工作台接着做 → 丢进 `_inbound/` 跑一次。
- 你要让 AI 代写客户回复、商品描述、公开回答 → 写完先过红线闸，`0/1` 可发，`2` 先改。
- 内部文档、代码、日志不用过红线闸——它只针对"要说出去的话"。
