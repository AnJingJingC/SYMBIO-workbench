# 入站与红线闸：补「入口」和「出口」各一道

> 起因：对照作者第 20 期《AI 全自动交付，未来已来》（2026-11-18）。他把客户消息当触发器、把价格退款做成代码过滤；我们原来两头都缺——只能在对话里等人开口，也没有任何一道闸管"说出去的话"。
> 本文只写已经落地、可跑、有自测的那部分；没做的写在最后一节，不写成已完成。

---

## 一、红线闸（出口）

**它管什么**：对外文本里的**承诺与合规**——价格、退款、收益、绝对化、合规词、贬损、时效承诺。三道既有闸（隐私、花费、负载）都在管"进来的东西"，这道是第一道管"出去的话"。

**用法**

- `node tools/redline-scan.mjs --text "这段话"`
- `node tools/redline-scan.mjs --file msg.txt`
- `echo "..." | node tools/redline-scan.mjs --stdin`
- 加 `--explain` 看命中原因与上下文；加 `--json` 给程序用
- `node tools/redline-scan.mjs --check-rules` 自检规则能否编译

**退出码决定要不要发**

- `0` 放行（无命中，或只有 L2）
- `1` 只有 L2 提醒：不拦，但建议再看一眼（限时、名额、时效承诺、贬损同行）
- `2` L1 硬拦：别直接发，要么删掉承诺，要么人来确认
- `3` 规则或用法有问题：**按"先别发"处理**，不要当成 0

**规则怎么改**

- 主规则 `config/redline-rules.json`，进版本库；每条有 `id` / `level`（L1 硬拦、L2 提醒）/ `why` / `patterns`（JS 正则源码）。
- 本机白名单 `config/redline-rules.local.json`，**只允许 `allowlist`**；写别的字段会被拒（3），防止一份本地文件把整道闸关掉。
- 白名单是**遮蔽**不是跳过：命中的短语被替换成等长占位符再匹配，所以"解释零风险是什么"这类句子可以放过，而同一句里别处的"零风险"承诺仍会被拦。

**纪律**：判不出就不放行。规则文件读不到、JSON 坏、正则编译不过、规则集为空，一律退出 3——空规则集等于放行一切，所以直接拒绝启动。

## 二、入站（入口）

**它管什么**：把"外部来的消息"变成看板上的任务，而不是只在你开口后才动。

**用法**

- 把来件丢进 `memory/50-inbox/_inbound/`（`.md` 或 `.txt`，一件一个文件，正文是原话）
- `node tools/inbound.mjs --once` 处理一轮就退出；`--interval 60000` 常驻每 60 秒扫一次
- `--once --dry` 只判定不派单、不动文件；`--json` 给程序用

**链路**：文件 → 隐私闸 → `route.mjs` 判场景（关键词优先、判不准才问免费桥）→ `bus dispatch` 落看板 → 归档到 `_routed/`。

**三个去向，各有含义**

- `_routed/` 派单成功；`_inbound-log.md` 记了场景与任务 hash
- `_unrouted/` 判不出来，**不硬猜**，等人指派
- `_blocked/` 隐私命中，**连路由都不走**——因为路由可能把原文发给免费桥，那就等于外发

**两条容易踩的纪律**

- 隐私闸必须先于路由：顺序反了，桥就成了外发通道。
- 重复件按正文 hash 识别，跳过且不重复派单；同一条消息转发两次不会变成两个任务。

**和顶层 `50-inbox/*.md` 的区别**：顶层是知识材料（`autopilot` 消化成卡片），本目录只做任务派单。混放会让同一份东西被两条链路各处理一遍。

## 三、面板上的两张卡（v0.5.6）

CLI 之外，业务面板新增并排两张卡，位置在指标区下方、工具箱上方。

**「发送前检查」**（`POST /api/symbio/outbound/check`）

- 贴一段要发出去的话 → 点「检查这段话」→ 本机正则判定，**不联网、不写文件**。
- 结果三档：放行 / 有提醒（L2）/ 拦下（L1，列出规则 id 与命中片段）。
- 只有放行与提醒才出现「复制文本」；**面板里没有「发送」按钮**——复制是让你自己粘到目标处发。
- 接口层同样 fail-closed：脚本缺失回 503、规则坏（退出码 3）回 `verdict=rule-error` 且 `allowed=false`、
  输出解析不出来回 `redline-parse-failed` 且 `allowed=false`。前端把这三种都显示成红字「按先别发处理」。

**「投递入站」**（`GET /api/symbio/inbound/pending`、`POST /api/symbio/inbound/scan`）

- 卡片显示「待处理 N 件」与归档计数（派单 / 未路由 / 被拦）。
- 「扫描并派单」是真动作：会移动文件、会写任务看板；「只判定不派单」走 `--dry`，不动文件。
- 待处理口径与 `inbound.mjs` 的 `listInbound` 严格一致（只认顶层 `.md`/`.txt`，跳过 `_` 与 `.` 开头）。
  两边口径不一致比不显示更坏——会变成"面板说 3 件、点了处理 0 件"。
- 退出码 `1`（有件需人看）**不是接口失败**：接口回 `ok:true` + `needsAttention:true`，
  面板照实列出每件的去向，不把"需要你看一眼"显示成"接口坏了"。

**空轮的契约（踩过一次）**：`inbound.mjs --json` 在没有待处理文件时原本什么都不打印，
面板拿到空 stdout 只能判成解析失败——把"没事干"报成"工具坏了"。已改为空轮也输出
`{"routed":0,"warn":0,"results":[]}`，并加了一条自测锁住。

## 四、自测与边界

**自测**：`node tools/dev/selftest.mjs` —— 191/0（红线 16 + 入站 14 + 其余既有断言）。
工作台侧 `npm run verify` —— 67/67（新增 5 条接口契约 + 10 条面板点击行为：放行/拦下/闸坏/网络异常/
入站 dry/目录不可读）。
红线闸的重点断言是四个 fail-closed 分支（坏 JSON、坏正则、空规则、本地改规则）；
入站的重点是"判不出来不硬猜""隐私命中不进看板""重复件不重复派单""空轮也回 JSON"。

**没做的部分（如实标注）**

- **不接微信/企业微信**。个人微信无官方接口，接它只能走界面自动化，随客户端版本失效且有平台规则风险；
  本链路只做到"你转发一次，其余自动"。要更自动，正路是邮件 IMAP 轮询（协议标准、可长期跑），
  需要账号与授权码，尚未做。
- **入站不负责回复**。它只把件变成任务；回复文本仍要单独过「发送前检查」。
  两张卡目前是"进来"和"出去"各一个动作，没有合成"读件 → 起草 → 过闸 → 我确认发送"的一条龙，
  这是有意留的：那一步必须有人按确认。
- **桌面操控仍是 0**。没做窄口自动化，也没有通用屏幕操控；这块作者自己也没跑通。

## 五、什么时候用

- 有人给你发消息/邮件谈业务，你要让工作台接着做 → 丢进 `_inbound/`，面板点「扫描并派单」。
- 你要让 AI 代写客户回复、商品描述、公开回答 → 写完先贴进「发送前检查」，放行/提醒再发，拦下先改。
- 内部文档、代码、日志不用过红线闸——它只针对"要说出去的话"。
