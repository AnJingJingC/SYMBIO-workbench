# 免费网页 AI 桥（T0 成本杠杆）

> 这是把成本压向 0 的核心手段：**付费 Agent 只负责发指令 + 拼接结果，真正写稿/写代码/批量脏活交给免费网页版 AI（豆包/千问/Kimi/智谱/DeepSeek 网页版）**。
>
> 本文件 2026-11-04 对照原作者源码（mashanglinyu/luanyujia-workbench · `10-源码/免费AI桥/webai.mjs` + `03-MCP接免费AI/`）**重写为真实机制说明**，不再停留在"人工流程"。

## 一、原作者的真实实现（三层 + 已登录浏览器）

```
AI 会话(决定问谁) ──调用工具──▶ 本地桥(壳注入脚本) ──发消息──▶ MCP 薄壳(每站一个)
                                                    │                │
                                                    │                ▼
                                                    │           网页版 AI(已登录的隐藏窗口)
                                                    │                │ 回答文本
                                                    ◀────────────────┘
       喂回上下文 ◀── 本地桥 ◀── MCP 薄壳
```

| 层 | 是什么 | 关键点 |
|---|---|---|
| ① 会话层 | 你的 AI 会话决定"这个问题问谁" | 它看到一个**普通工具**，不知道背后是网页 |
| ② 本地桥 | 注入到工作台页面里的脚本（作者的 main.js 桥服务 `127.0.0.1:31239`） | 负责"页内 ↔ 主进程"转发（页面不能直接起进程） |
| ③ MCP 薄壳 | 每个站一个薄壳（webai-doubao / webai-tongyi / …） | 只做三件事：**输入 → 等稳定 → 取文本** |
| ④ 网页版 | 一个**已登录**的浏览器窗口（通常隐藏） | 登录态是整套东西的前提，也是最脆的环节 |

> **为什么能零成本**：你花的是**已付过的订阅额度**，不是按 token 计费的 API。代价是本地一点 CPU/内存（跑一个隐藏窗口）。

### 三个值得抄的设计决定
1. **薄壳很薄**：站点差异只在一个对象里（`{id,name,url,inputSel,send,answerSel,wait,profileDir}`），流程代码全站共用 ⇒ 加站≈加一个对象。
2. **等待分两步**：先等"文本出现"，再等"stableMs 内不再变" ⇒ 只等出现会拿到半句话（最常见实现错误）。
3. **登录态用持久化 profile，不做自动登录**：首次手动登录一次后复用；代码里模拟登录几乎必触发风控。

### 硬性约束（决定它"只能干轻活"）
| 代价 | 表现 |
|---|---|
| 慢 | 一次问答几十秒；不适合长任务、不适合批量 |
| 脆 | 对方改一次 DOM，选择器就过期 |
| 不能并发 | 同一个站两个页面同时问答几乎必然串话 |
| 依赖登录 | 掉登录 / 风控验证码 ⇒ 全挂 |

> 判据：**适合"问一次、要一段文字"；不适合"跑一百次"或"必须准时"。**

## 二、在本工作台（标准 DSH 0.2.1）下的可行路径

原作者那套依赖**自研 Electron 壳的桥服务**，标准 DSH 没有这一层 ⇒ **不能直接 drop-in 他的 webai.mjs**。

要在本工作台真跑起来，需自建一层（独立基建，不在本仓库内置）：

1. **MCP 薄壳**：用 Playwright/Puppeteer 起一个本地 MCP 服务，每个站一个对象（同作者的薄壳结构）。
2. **已登录 profile**：首次手动登录一次，之后复用 profile 目录（不自动登录）。
3. **等稳定逻辑**：照搬"出现 + 不再变"两步等待。
4. **落盘只回预览**：长回答存文件、终端只回前 600 字（省上下文，作者关键设计）。

> ⚠️ 这条路径需要你自备：① 浏览器自动化运行时（Playwright/Puppeteer）；② 各站登录态。
> 属于外部基建，是否投入另议。**本仓库当前不内置程序化桥。**

## 三、今天就能用的人工桥（零额外基建）

1. 在浏览器开 2–3 个免费网页 AI（各一个标签）。
2. 让 DSH 生成**一段可直接粘贴的指令**（背景 + 要求 + 输出格式），你复制粘贴到免费网页。
3. 把免费端输出复制回 DSH，说"按这个整理成卡片 / 合并 / 校对"。
4. DSH 只做"整理 + 落盘"，不重复生成大段内容。

> token 成本主要在"指令 + 整理"，大头生成在免费端，实测能把单次成本压到几毛甚至 0。

---

## 四、红线约束（不可绕过）

- 喂给免费网页 AI 的内容**必须先过 `pii-scan`**；L1 一律不发，L2 脱敏后才可发（红线 1）。
- 免费网页 AI 的输出**默认"待核实"**，DSH 落卡片前要交叉验证，不得直接当事实（红线 3）。
- 长回答存盘时**落盘一律 Markdown**（作者 2026-09-21 定的规矩）：给目录/无扩展名 ⇒ 自动 `webai-<站点>-<时间戳>.md`；`.txt` ⇒ 改 `.md`。

## 五、与本工作台其他机制的关系

- `model-probe` / `spend-guard` 管"DSH 内部模型"的成本；免费网页桥是"DSH 外部算力"，两者叠加才是完整"免费优先"。
- `load-gate` 管"本机负载"；免费网页桥吃本地一点 CPU/内存，重活前也该先过 load-gate。
- 这条桥是**可选增强**，不做也不影响 A 包跑通。
