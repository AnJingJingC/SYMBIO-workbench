## 2 · 简介（一句话，直接粘贴）

```
把六层记忆、三层库与免费 AI 桥挂进 DSH Desktop 的四处宿主座位：业务面板 / 常驻状态条 / 侧栏入口 / 协同总览页。
```

字数约 60，适配列表卡片。**不要用**旧版那句话（「单主场景「知识消化」…一块业务面板」）——那是 0.4.0 的形态，已过时。

## 3 · 长描述（详情页 / 提交页允许填长文时用）

```markdown
SYMBIO 工作台不是一个新的聊天窗口，而是把「你在 DSH 里做的事」摆到你能看见的四个地方。

■ 业务面板（主入口）
长文丢进去 → 六层记忆消化 → 出知识卡片。数据源灯、桥灯、亮灯胶囊、负载胶囊、版本、刷新，一屏看全。

■ 常驻状态条（右下角）
跨页可见的一条胶囊：几处活动、在跑哪个场景、CPU/内存、能不能派单、待办几件。
它是全帧表面且 pointer-events 恒为 none —— 永远不会挡住宿主自己的按钮。

■ 侧栏入口 + 协同总览页
左侧栏多一个准星图标，有活动时右上角亮绿点；点开中央区换成整页「协同总览」：
亮灯明细、负载明细、三层库、系统拓扑、待办、六层记忆。

三个新座位共用一口数据井（state 30s / activity 5s / load 20s），全包只有三个定时器。
拿不到 slots 服务时只降级这三处附加 UI，业务面板照常挂载 —— 这是有意的降级路径。

■ 诚实边界
· main 座位是切换不是同屏：点开总览页时业务面板会被替换，这是宿主契约决定的。
· 常驻状态条不可点击（设计如此，不是缺陷）。
· 桥的登录态长期稳定性未验收；四个站点的选择器随网页改版可能失效，有现场重试工具。

MIT 许可，本体零依赖，不含凭证与用户数据。
```

## 4 · 截图建议

市场卡片一般要 1–3 张。按价值排序：

1. **业务面板全貌**（能看到顶部六个胶囊 + 知识卡片列表）——这是主入口，第一张必须是它
2. **右下角常驻状态条 + 左侧栏准星绿点**（可裁一条横向区域，标出两个位置）
3. **协同总览页**（整页，亮灯明细与负载明细可见）

真机截图在私仓 `reports/` 与 `shell/_selftest/` 里有历史素材，但**提交前请重新截**——0.5.1 的胶囊文案与布局以当前装机为准，别用 0.4.0 的旧图。

## 5 · 提交前的三条自检

1. **包是不是这一份**：`md5sum symbio-workbench-0.5.1.tgz` 应为 `4aab4e39377bc68d2e8874ca0676de2a`。若不是，别提交——先查是不是旧版本残留在上传目录。
2. **仓库根只有当前版本一个 tgz**：多一个旧包，下载的人就可能装到旧包，而安装过程没有任何提示。
3. **`package.json` 里没有需要现补的字段**：`dsh` 只有 `bundle` 与 `client`，没有 `dsh.id`。安装器不要求它（真机装过五个版本都能装），**若提交页强制要 id，按页面提示补，不要凭猜改包**。

## 6 · 提交之后：验收标准第 4 条的唯一一次真实验证

这一步是整个项目验收里唯一还没做过的事：**从市场安装一次，看装的是不是 0.5.1**。

装完只看三件事，不看别的：

1. 宿主报 `application: applied`（不是 applied 就别说装好了）
2. **重启 Harness 之后**读 `已加载.json`，版本必须是 `0.5.1`
3. 业务面板还在、右下角胶囊在、左侧栏准星在；点准星能换出总览页

第 2 条最关键：`applied` 只代表写进代际清单，运行中的进程还加载着旧代际——不重启会看到旧面板，然后把「没生效」误判成「市场装坏了」。

## 7 · 如果提交页问「怎么装」

```
把仓库根或 INSTALL-PROMPT.txt 里的提示词粘进 DSH Desktop 新会话即可；
安装被宿主唯一授权给 Plugin Manager，同名升级用 replace: true。
装完必须重启 Harness 才算接管。
```
