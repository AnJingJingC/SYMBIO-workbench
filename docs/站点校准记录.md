## 二、怎么校准（可复现的四步）

以任一新站为例：

```bash
cd E:/SYMBIO/shell
npm run bridge                                    # 1. 起桥
curl -X POST "http://127.0.0.1:31239/webai/show?site=<id>"   # 2. 弹窗手动登录
node probe-site.mjs <id>                          # 3. 探测：登录态 / 输入框 / 回答区
```

**第 4 步是关键：回答区只能"先问一句"才能校准。**

回答容器在没提问时根本不存在于 DOM 上。所以：

```bash
# 先发一问（可能因 answerSel 猜错而超时，但问题已经发出去了，页面上会留下回答）
curl -X POST -H "content-type: application/json" \
  -d '{"site":"<id>","question":"用一句话说明什么是索引。"}' \
  http://127.0.0.1:31239/webai/ask

# 再探测：会列出页面上所有承载正文的最内层容器（文本块清单）
node probe-site.mjs <id>
```

从文本块清单里认出"答案容器"的 class，然后**现场验证候选**（不写回文件、不重启）：

```bash
node probe-site.mjs <id> --answer ".候选选择器"
# 或用批量探针一次试多个
node cali-candidates.mjs <id> ".候选1" ".候选2" ".候选3"
```

命中且文本确实是答案 → 回写 `sites/<id>.mjs` 的 `answerSel`，把 `verified` 改 `true`，然后重启桥复验。

```bash
node probe-site.mjs <id>     # 期望：结论 ✓ 校准通过
```

## 三、这次踩到的五个坑（都写成了测试）

### 1. 「已登录」被误判成「未登录」

`loggedIn()` 的判据是"输入框在不在"。输入框选择器猜错 → 已登录也报未登录。

真机证据：DeepSeek 页面明明白白写着脱敏手机号 `137******86`，智谱写着 `用户_xKhkop … 退出`，但 `probe` 报 `loggedIn:false`。

**教训**：`loggedIn:false` 不等于"要去登录"，先看页面正文有没有用户痕迹。

### 2. 抓到的是名片卡，不是答案（智谱）

`.answer-content` 命中了侧边栏的智能体名片卡，文本只有「ChatGLM」——7 个字，`ok:true`。

**教训**：`ok:true` 只代表"取到了非空文本"，不代表取对了。必须看内容。

### 3. 思考过程被当成答案（智谱）

页面同时有两块 `.markdown-body`：

- 祖先 `.answer-content-wrap.text-advance-thinking-content` → 190 字推演（思考）
- 祖先 `.answer-content-wrap` → 63 字结论（答案）

用 `:not([class*="thinking"])` 精确排除。**和豆包 11-04 那次「正在思考」事故是同一类问题**：占位/中间态不是答案。

### 4. 隐藏窗口里 Enter 永远不生效（最隐蔽）

桥的网页窗口默认隐藏。隐藏状态下：

- 文字**能**写进 contenteditable 的 DOM
- 但 Enter **不生效** → 没有问句、没有回答 → 表现为「首帧超时：35s 内没有出现新回答（可能没发出去）」

这个错误信息会把人引向"选择器失效/站点改版"，实际是窗口可见性。

真机对照：同一句话，隐藏窗口 71 秒两次超时；`/webai/show` 显示窗口后 5.6 秒答完。

**修复**：`post()` 发送前检查窗口可见性，隐藏就先 `setVisible(true)` 再发送（只显示一次，之后保持可见）。

### 5. 追问引导语每次换措辞（千问）

- 「需要我**为你整理**一份报告吗？」
- 「需要我**继续用一句话为你解释**“事务”吗？」
- 按钮提示：「好的，继续」「好的，**帮我解释**」

按前缀枚举永远漏。改成**按结构删**：以「需要我」开头且以问号结尾的整行、以「好的，」开头的短行。

引用角标同理，可能在行尾（`…效率。13`）也可能夹在句中（`…安全审计。348`）。

## 四、工具上补的三件事

| 工具 | 原来 | 现在 |
|---|---|---|
| `probe-site.mjs` | 只能验证"你写的选择器对不对"，猜错就什么都看不到 | 支持 `--input/--send/--answer` 现场试候选；直接打印页面文本块清单 |
| `cali-candidates.mjs` | 不存在 | 一次试多个候选，输出命中数 + 首/末节点文本 + 是否含关键字 |
| `probeDom` | 只按 `answerSel` 查 | 增加 `textBlocks`：页面上所有最内层正文容器（tag/class/testid/文本头） |

`textBlocks` 是这次最有用的东西：它让"我猜错了"和"这个站没有回答区"变成两件可以区分的事。
