## 第一项：桥登录态复验（约 3 分钟）

**为什么**：免费桥是成本命脉。上次首跑读到「需登录」判 FAIL 是真实信号，不是脚本 bug；销账的唯一方式是重登后再跑一次拿到 `EXIT=0`。

**步骤**

1. 确认桥在跑：浏览器打开 `http://127.0.0.1:31239/health`，看到 `ok: true`。没起就在**沙箱外**跑 `E:/SYMBIO/shell/bridge-autostart.cmd`（不要在 DSH 会话里起，沙箱会拦 Electron 子进程）。
2. 让豆包窗口出来，**手动完成登录**，关掉窗口。
3. 在沙箱外执行：
   ```
   node E:/SYMBIO/shell/test-login-window.mjs --recheck
   ```

**判定**

- 输出末尾 `EXIT=0` → **销账**：跨日登录态成立，桥可用。
- `EXIT=3` → 登录态仍失效。**别重复扫码**，先看窗口里是不是被换成了别的站点或未登录 profile，记下现象再回来。
- 在 DSH 会话里跑可能看到 `exit code 1`：那是执行层把非零码统一包装，脚本自己定义失效为 3，以输出文本为准。

## 第二项：会话衔接菜单点测（约 2 分钟）

**为什么**：衔接动作已装、契约测试全过、座位名对宿主 SlotMap 核验过，唯一没验的是「这个座位到底有没有挂进会话菜单」。这是 WebView 内部渲染，外部探测一律 401，只能肉眼。

**步骤**

1. 开任意一个对话。
2. 点会话标题旁的「⋯」。
3. 找一项 `⇄ SYMBIO 换会话衔接（复制提示）`。
4. 点它一次，然后在任意输入框 `Ctrl+V`。

**判定**

- 菜单里有该项、粘贴出的是交接提示（含「当前状态 / 下一步 / 未决问题 / 关键路径」四段）→ **销账**，半自动衔接可用。
- 菜单里没有该项 → 问题锁定在「座位挂载」层（不是包、不是文件）。此时不要重装，回来告诉我，我去查宿主是否加载了该座位。
- 有该项但粘贴为空 → 是服务端 `/handoff/prepare` 没返回内容，把当时面板是否有报错记下来。
