# 会话衔接菜单 · 真机点测指南（v0.5.5）

## 目标
验证 v0.5.5 在 DSH Desktop 里，**会话「⋯」菜单真出现「SYMBIO 换会话衔接（复制提示）」按钮，点击后真生成衔接提示并写进剪贴板**——把 v0.5.5 从「脚本/契约层就绪」销账到「真机可用」。

> 诚实边界先立住：这是**半自动衔接**，不是「一键换对话」。本动作只生成提示 + 复制；**新建对话、粘贴、旧对话归档仍由人完成**。宿主不开放 `createConversation` / `archiveConversation` 之类的动作 API，任何声称一键换会话的说法都不成立。

## 代码层已固化（契约测试 46/46 覆盖，真机不用重复验）
- 座位：`sidebar.workspaces.session.menu.item`，独立 id `symbio-handoff`，`order=500`，label `SYMBIO 换会话衔接（复制提示）`；`replaceRisk=none`，不 shadow 宿主任何 shipped 项（pin/rename/fork/archive/session-id）。
- 动作自持：点击只调我方 `POST /api/symbio/handoff/prepare`，**零宿主会话 API 调用**。
- 服务端：只读 `dataRoot/memory/20-scenes/knowledge-digest/当前交接.md`，截前 8000 字，拼成四段提示返回 `{ ok, prompt, chars, source, truncated, mode:'semi-automatic', hint }`；缺文件 404 `handoff-unreadable`、空文件 422 `handoff-empty`，**不写盘、不建会话**。
- 客户端：拿到 `prompt` 后 `navigator.clipboard.writeText`；失败标 `error` 并提示「剪贴板不可用」，**不谎称已复制**。

## 前置
1. DSH Desktop 已装 v0.5.5 面板包：`symbio-workbench-0.5.5.tgz`，md5 `88609cee0ffac1f14f92469c1e48e03c`（旧 0.5.4 包须已移除，避免下载者拿到无衔接菜单的旧版）。
2. 工作台数据根里 `memory/20-scenes/knowledge-digest/当前交接.md` **存在且非空**（v0.5.5 前该机制已跑通，正常应有内容）。
3. 宿主给面板 webview 剪贴板写权限（多数宿主默认给；若不给，见下方「失败排查」）。

## 真机点测步骤

### A. 菜单可见性
1. 进 DSH Desktop，打开任一会话。
2. 点会话行的「⋯」菜单。
3. **应看到**末尾多出一项 `⇄ SYMBIO 换会话衔接（复制提示）`，排在宿主自带项（pin/rename/fork/archive 等）之后。
   - 看不到 → 跳到「失败排查 ①」。

### B. 点击动作
4. 点该项。按钮立刻变 `生成衔接提示…`（busy），随后：
   - **成功**：前面图标 `⇄` 变为高亮色，悬停 tooltip 显示 `已复制 N 字衔接提示 → 请手动新建对话并粘贴`；
   - **失败**：图标变红，tooltip 显示具体原因（见「失败排查 ②③」）。
   - 注意：**按钮文字在成功/失败后都回到固定文案**，状态只体现在图标颜色 + tooltip + DOM 属性 `data-symbio-handoff`（值 `idle|busy|done|error`）。这是当前实现的可观察形态，别误以为「点了没反应」。

### C. 粘贴验证（半自动的最后一环）
5. 手动在宿主新建对话（这一步宿主没人机 API，只能手点）。
6. 在新对话输入框粘贴（Ctrl/Cmd+V）。
7. **应粘出**以 `【SYMBIO 会话衔接】新一轮对话请从这里续上：` 开头的提示，内含 `当前状态 / 下一步 / 未决问题 / 关键路径` 摘录，末尾带「如与事实不符，以文件与对话历史为准」免责句。
8. 新对话按提示续上，确认衔接内容对得上现状。

### D.（可选）API 层冒烟——不依赖菜单，用来隔离「是按钮问题还是接口问题」
在面板服务所在环境直接打接口（端口以宿主面板实际监听为准；客户端用的是相对路径，无需硬编码端口）：

```
curl -s -X POST http://127.0.0.1:<面板端口>/api/symbio/handoff/prepare \
  -H 'content-type: application/json' -d '{}'
```

- `ok:true` + `prompt` 非空 + `mode:"semi-automatic"` → 接口正常，问题在菜单/剪贴板。
- `errorType:"handoff-unreadable"` → 数据根没找到交接文件（前置 2 不满足）。
- `errorType:"handoff-empty"` → 交接文件是空的，先写交接再点。
- 接口层契约已有自动化覆盖（缺文件 404、空文件 422、读真实交接 1707 字），真机一般不必跑这步。

## 判定标准（三项全中才销账）
- [ ] 会话「⋯」菜单出现独立衔接按钮，未 shadow / 顶掉宿主项。
- [ ] 点击后生成非空提示，且剪贴板里拿到以 `【SYMBIO 会话衔接】` 开头的文本。
- [ ] 新对话粘贴后能按「下一步」续上，提示注明「以文件为准、不照抄旧状态」。

## 失败排查
1. **菜单里没这个按钮**：确认装的是 0.5.5（不是 0.5.4）；该座位由 `sidebar.workspaces` entry 声明、宿主 `client-ui-workspace` 才会挂载——若宿主版本不加载工作区会话菜单，此项记为宿主受限，不伪造。
2. **点了报「读不到交接文件」**：数据根路径不对或文件缺失；在面板「数据源诊断」看实际 dataRoot，确认 `memory/20-scenes/knowledge-digest/当前交接.md` 存在。
3. **点了报「交接文件为空」**：先让工作台流程写一次交接（会话内覆盖写 `当前交接.md`，≤4KB），再点。
4. **「剪贴板不可用」**：宿主 webview 没给剪贴板权限。此时接口已生成提示、只是没复制——可用上面 D 步的 curl 拿到 `prompt` 手动复制，或让宿主放开 `clipboard-write` 权限。不要因为这一条就判「衔接功能不可用」。

## 已知边界（诚实）
- 真机点测需 DSH Desktop 主进程 + 会话菜单 + 剪贴板权限；本机（仅有 dsh-pet 进程、无 Desktop 主进程）无法代跑，**代码/契约/API 层全过不等于按钮真出现**，须本人在 DSH Desktop 点一次确认。
- 只产出提示，**不新建 / 命名 / 归档会话**；「历史对话自动归档」作者靠自研壳，我们宿主没开口子，属受限项，不追。
- 交接文件截前 8000 字；超长时返回 `truncated:true`，真机若发现关键「下一步」被截掉，应先把 `当前交接.md` 压回 ≤8000 字，而不是放宽接口上限。
- **UX 待优化（下一版可考虑）**：当前成功/失败只在图标颜色 + tooltip 体现，按钮文字不变，鼠标不悬停时反馈偏弱。若真机确认这点影响使用，下版可让 `done` 状态按钮文字直接显示「✓ 已复制 N 字 → 去新建对话」、`error` 显示错误摘要。本版不改，先验证菜单是否真出现（若座位不挂载，改文案也无意义）。
