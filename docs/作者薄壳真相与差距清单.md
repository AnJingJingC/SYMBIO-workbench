## 一、薄壳真相：作者用的是 Electron，不是 Playwright

**Q：作者源码里有没有 Playwright MCP 薄壳？**
**A：没有。** 全仓库 `Playwright` / `playwright` / `puppeteer` 命中 **0 次**。

作者实现"免费网页 AI 桥"的真实技术栈：

| 层 | 实现 | 文件 |
|---|---|---|
| 桥服务 | 本地 HTTP `127.0.0.1:31239/webai/ask`（由 `main.js` 起） | `12-源码照搬/外壳/main.js` |
| 网页驱动 | **Electron `<webview>`**（非 Playwright/CDP） | `12-源码照搬/外壳/renderer/webai-bridge.js` |
| 登录态/预热 | 复用顶栏那套 `<webview>`（`partition=persist:webai-<key>`），窗口**可见** | 同上 |
| 打字/发送 | Electron 输入事件：`wv.sendInputEvent` / `wv.focus()` / `wv.insertText()` | 同上 |

仓库里确实有一个 `模板/MCP-站点薄壳.mjs`，但它：
- 第一行就写 **"这是骨架，不是能直接跑的实现"**；
- 依赖一个你自己实现的 `bridge` 对象（`openPage/fill/waitStable`），而这个 bridge 在作者那边就是上面的 Electron webview IPC；
- 5 处 TODO 必须按 F12 现量每个站的选择器；真实各站实现作者注明 **"成品保留（不在这个仓库）"**。

**所以：** 作者既没用 Playwright，那个"薄壳"也**不可直接照搬**——它长在 Electron 壳上，标准 DSH 没有这层壳。若要真把免费桥跑起来，得**自己建桥**（Playwright / CDP / 无头浏览器各站一个已登录 profile），这正是上轮我建议的方向，与作者技术栈无关。

## 三、一句话结论

- **没有 Playwright 薄壳**，作者用的是 Electron `<webview>` 桥；他那个"薄壳"是绑壳骨架、真实实现未公开，对我们**不可复制**。
- 我们**不是**在作者"初始版"后面追赶：在「标准 DSH 可运行的通用核心」上，我们比他公开的代码**更完整**（10 技能 + 6 工具 + 记忆/配置都真实可跑）。
